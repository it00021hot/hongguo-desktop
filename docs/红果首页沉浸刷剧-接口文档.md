## 2. 每个请求都遵守的公共约定

### 2.1 版本身份与 UA（唯一出处 `hongguo-signer::device`）

- `APP_ID = "8662"`（`AppProperty.getAppId` = `0x21d6`）。query 渠道 `BUILD_CHANNEL = "update_64"`
  （`assets/ss.properties` 的 `meta_umeng_channel`）。Medusa 密文里的 `CHANNEL_ID` 仍是旧常量。
- 版本身份：`APP_VERSION_CODE = 74332`、`APP_VERSION_NAME = "7.4.3.32"`，注册常量同值。
  `SecLinkInitIdleTask` 的日志串是 `,version=7.4.3.32,channel=`。
- 业务 UA（`video_ua()`）：
  `com.phoenix.read/74332 (Linux; U; Android 14; zh_CN; Xiaomi 14; Build/UKQ1.230804.001;tt-ok/3.12.13.20)`
  尾段必须是 `tt-ok/…`。本包里同时有 `okhttp/3.12.13.20` 和
  `SsOkHttp3Client` 的 `tt-ok/3.10.0.2`。

### 2.2 设备档案（query 的公共参数，**保序**）

签名 query 的开头是设备档案全字段，顺序即签名顺序，绝不排序/去重：

`ac, aid, app_name, channel, compliance_status, device_brand, device_platform, device_type, dpi, dragon_device_type, host_abi, is_android_pad_screen, language, manifest_version_code, os, os_api, os_version, player_so_load, pv_player, resolution, ssmix, update_version_code, version_code, version_name`（+ `cdid`/`openudid` 视身份）。

- 匿名档案：**不带 `iid`/`device_id`/`openudid`，零 cookie**（带未知 install_id 反而被拒）。
- 注册档案：带 `cdid/openudid/device_id/iid` + `install_id`/`ttreq` cookie。
- 版本身份（`version_code/update_version_code/manifest_version_code/pv_player`）与 UA 必须成套。

### 2.3 请求形态两族（别混）

| | lq 域 reading 系 | sinfonlineb / 取流系 |
| --- | --- | --- |
| 头 | `x-ss-dp: 8662` + `lc: 101` + `x-reading-request: {ticket_ms}-{rand}`，**无五件套** | 全签名五件套（见 2.4） |
| POST body | 一律 gzip（`Content-Encoding: gzip`） | 取流走 gzip；landpage 未压缩 |

### 2.4 签名五件套（`hongguo-signer::ticket::sign_request_with`）

生成的签名头：`User-Agent`、`Accept: application/json; charset=utf-8,application/x-protobuf`、`x-xs-from-web: 0`、`x-ss-req-ticket: {ms}`、`sdk-version: 2`、`passport-sdk-version: 5051452`、`x-vc-bdturing-sdk-version: 4.0.3.cn`、`x-khronos: {s}`、`x-ladon`（b64(be32(khronos))）、`x-argus`（b64(le32(khronos))）、`x-gorgon`、`x-helios`、`x-medusa`；POST 另加 `Content-Type: application/json; charset=UTF-8` + `x-ss-stub`（body 的 MD5 大写）。**不带** `x-tt-dt` / `x-tt-request-tag`。

- query 末尾追加 `ts={khronos}` + `_rticket={ticket}`；`_rticket` 逐毫秒抖动以避开 x-argus 的 `branch=1`（该档服务端不受理）。
- 取流请求再叠加 `x-ss-dp` + `lc` + `x-tt-store-region: cn-gd` + `x-tt-store-region-src: did` + `Content-Encoding: gzip` + 档案 cookie；登录态带 `x-tt-token` 的前 56 字符。
- ⚠️ **签名是「URL + query + body + 时间戳」的联合函数**，签完不能再动 url/body/query（含 query 顺序与 URL 编码方式）。

### 2.5 响应与错误信封

- 响应普遍为 **brotli 压缩 JSON**（请求带 `accept-encoding: gzip, deflate, br`）。
- reading 系错误信封：小写 `code`，`code==0` 即成功（`check_code`）。
- 取流接口错误信封：**base 族**，大写 `Code` + `BaseResp.StatusMessage`（`check_model_code`）。
- **`HTTP 200 + 0 字节` = 静默拒绝**，两种成因：① 无签名/签名失配；② 匿名观看配额耗尽（官方匿名播到第 9 集也会 200+0 并弹登录）。判定要先看响应字节数，不能只看状态码。

## 3. 首页沉浸式刷剧：完整请求时序

```
冷启动预热(行为铺垫)
  → 设备注册(取流/登录需要)
  → 顶栏 tab 列表
  → 首页推荐流首屏
  → 翻页(持续下滑)
  → 点开一部剧 → 分集详情 preload
  → 取播放流(批量/单集 + 回退)
  → CDN 拉流(Range)
  → 进度上报(播放心跳)
```

### 第 0 步：冷启动行为预热（`warmup.rs`）

官方冷启动约 40s 摊 ~120 条请求，仓库把序列固化为 `warmup_sequence.json`
（host + path + body），运行期按序重发：身份字段重写为当前设备、逐条重签名、60ms 间隔。
作用是把设备「行为画像」铺到位，个别失败不中断整体。

### 第 1 步：设备注册（需要取流/登录时）

`POST https://log5-applog-lf.fqnovel.com/service/2/device_register/`

- query 固定 4 参：`tt_data=a, cronet_version=8d40f833_2026-03-03, ttnet_version=4.2.243.31-douyin, use_store_region_cookie=1`。
- 头：注册口径 UA + `content-type: application/octet-stream;tt-data=a` + `lc: 101` + `log-encode-type: gzip` + `x-ss-dp: 8662` + `x-ss-req-ticket` + `sdk-version: 2` + `passport-sdk-version` + `x-vc-bdturing-sdk-version` + `x-neptune` + `x-ss-stub`（body MD5 大写）；零 cookie。
- body：**TT-Encrypt V5** 加密的注册指纹 JSON（magic + salt + AES-128-CBC + gzip payload）。
- 出参：`device_id / install_id / device_token` + Set-Cookie `install_id` / `ttreq`。`device_id: 0` = 被静默拒。

### 第 2 步：顶栏 tab 列表

`GET https://api5-normal-lq.fqnovel.com/reading/bookapi/bookmall/tab/v?client_req_type=4&tab_type=16`

- 一次 cr=4 请求的 `tab_item[]` 即完整顶栏：关注 45 / 漫剧 36 / 真人剧 39 / 推荐 16。
- 推荐 tab 带 `bookstore_id`（= 翻页 `cell/change` 的 `plan_id`，每 tab 不同）。
- 官方启动首拉用 `tab_type=16&client_req_type=1028`（只回 4 条 tab_item，不带 feed，首屏走本地缓存）。

### 第 3 步：首页推荐流首屏

`GET https://api5-normal-sinfonlinec.fqnovel.com/reading/bookapi/bookmall/tab/v?client_req_type=1028&tab_type=<T>`

切频道才发 `cr=4&tab_type=<T>`（响应 `tab_item[T]` 自带该频道 feed）。核心 query
（与抓包逐字段一致，另加设备档案注入）：

```
filter_ids=, last_search_query_from_rec=false, rec_filter_info_list=,
bottom_tab_type_list=7,0,1,2,3,4, last_tab_index=0,
is_video_feed_tab_first_request_cold_start=true, is_horizontal_screen=false,
screen_width_px=1078, tab_type=<T>, image_shrink_datas_str=<FEED_IMAGE_SHRINK>,
disable_digg_stat=false, client_req_type=1028, need_personal_recommend=1,
recommend_extra=<RECOMMEND_EXTRA>, rom_version=V417IR release-keys, ...
```

另带 `session_runtime_pairs` 18 项运行时上下文（`normal_session_id={uuid}#1`、
`cold_start_session_id={uuid}`、`network_type=4`、`screen_brightness=21`、
`battery_pct=71`、`app_dark_mode=1` …）。

**响应解析**：`tab_item[T]` 里按**内容**找 cell，不能按位置取（`[0]` 可能是空金刚位卡
show_type=583）。推荐流是嵌套 `cell_data[].video_data[]` 非空的那个 cell
（cell_name「猜你喜欢」、show_type=407）。从它取 `cell_id` + `bookstore_id` +
`session_id`，并把 `video_data[]` 解析成首批条目（字段见第 4 节「响应处理」）。

### 第 4 步：推荐流翻页（下滑加载）

`GET https://api5-normal-sinfonlinec.fqnovel.com/reading/bookapi/bookmall/cell/change/v`

三件套：`cell_id`（目标 tab 自己的）+ `plan_id`（= bookstore_id）+ 会话/游标：

- `session_id`（首页响应下发，原样回传）
- `offset`（上一页响应的 `next_offset`，0 → 6 → 12 递进）
- `filter_ids`（已下发过的 series_id 逗号表，服务端排除已见 → 翻页不重复）

其余业务零值族照抄（`change_type=0, client_req_type=2, client_template=7, genre=0,
gender=2, screen_width_px=1078, …`）+ `rec_filter_info_list`（最近曝光环回传，个性化去重上下文）。

响应解析：`data.cell_view.cell_data[].video_data[]` + `has_more / next_offset / session_id`。

### 第 5 步：分集详情（点开一部剧）

`POST https://api5-normal-sinfonlinec.fqnovel.com/novel/player/multi_video_detail/preload/v1`

body（gzip JSON）＝ `detail_payload`：`biz_param`（9 字段，`detail_page_version=0,
screen_width_px="1078", source=7, use_os_player=false, use_server_dns=false, …`）+
`dr_scene="preload"` + `series_id`（**逗号串可批量**，官方 6 部一发）。

响应：`data[series_id].video_data.video_list[]`（每集 `vid` + `content_type` + `duration`），
并把 vid→content_type 注册进取流分组 key 的来源。

### 第 6 步：取播放流（最关键，多通道 + 回退）

| 通道 | 方法 + 端点 | body |
| --- | --- | --- |
| 批量·主 | `POST https://reading.snssdk.com/novel/player/multi_video_model/v1/` | `saas_model_payload`：`biz_param` 10 字段（`device_level=3` 即 High，`use_server_dns=true`，`use_server_dns_scene="cold_start_stage"`，`video_platform=1024` 即 Mixed）+ `mixed_video_id_map`。**没有** `dr_scene` |
| 批量·次 | `POST https://reading.snssdk.com/novel/player/multi_video_model/player/v1` | `player_model_payload`：同上 biz，另加 `dr_scene="player"`。只在主请求缺流时打 |
| 批量·末 | `POST https://api5-normal-lq.fqnovel.com/novel/player/multi_video_model/v1/` | `model_light_payload`：`biz_param` 8 字段（`device_level=4, use_server_dns=false`）。`device_level=4` 不在本包 `DeviceLevel`（Low=1 / Middle=2 / High=3）里，只留作最后一跳 |
| 单集·主 | `POST https://api5-normal-lq.fqnovel.com/novel/player/multi_video_model/v1/`（主域同路径备选） | 旧 `model_light_payload`（`device_level=4`）→ 本机能播的 `bytevc1`。桌面先打这条 |
| 单集·回退 | `POST https://reading.snssdk.com/novel/player/video_model/v1/` | `single_model_payload`：常只给 `bytevc2`，系统播放器挑不中时才走到这里 |

- **`mixed_video_id_map` 的 key = 条目 content_type 的原样字符串**（错配 → 不发货）：
  漫剧 1004→`"1004"`、真人剧 1→`"1"`、书城 1001→`"1001"`。
- 三路都走签名五件套（`api_call_model_light`）。空字节 / 请求失败 / 响应不可用 /
  无可播放流 → 逐级回退。
- **响应处理**：`data.{vid}.video_model` 是 **JSON 字符串**（批量一次回多集；
  单集新通道另兼容 `/data/video_model`）。二次解析后是各档位流（`bytevc1` 旧 /
  `bytevc2` 新私有编码，本机可能不支持）+ `spade`（加密密钥材料）。`stream_pick`
  按档位 + 解码能力选流。`video_model` 非空 ≠ 可播（bytevc2 打不开要回退）。

### 第 7 步：CDN 拉流

对选出的直链发 `GET` + `Range: bytes={start}-{end}`，`User-Agent=video_ua()`、
`Accept-Encoding: identity`（保持 MP4 原始字节，禁 HTTP 压缩）。403 补 Referer 重试一次。
206 直接收该段；200（CDN 忽略 Range）边收边切。

### 第 8 步：进度上报（播放心跳）

成对打两个接口（起播 5s 首报 + 每 ~60s + 暂停/切集收尾）：

- `POST /reading/bookapi/read_history/update/v` —— `book_id`/`vid` 是 **JSON 数字**。
- `POST /reading/bookapi/read_progress/upload/v` —— `book_id`/`item_id` 是 **字符串**。

官方传 0 的字段（duration/episode_cnt/retain 等）照抄 0。`vid_index` 线上协议 0 基。

## 5. 对齐时的关键陷阱（务必照抓包，别凭「也能用」）

1. **签完不能动 url/body/query**；query 顺序、URL 编码方式都是签名的一部分。
2. **`200 + 0 字节` 是拒绝不是成功**，先看字节数再看状态码。
3. **取流错误信封是大写 `Code`/`BaseResp`**，reading 系是小写 `code`，两套别混。
4. **`mixed_video_id_map` 的 key 必须是 content_type 原样字符串**，错配不发货。
5. 首页推荐流要按**内容**找 cell（猜你喜欢 show_type=407），按位置取 `[0]` 会取到空金刚位。
6. 翻页**必须带 `filter_ids`**，否则服务端不做会话内去重、会重复刷已看过的剧。
7. 匿名档案**零 cookie**、UA 尾段必须 `tt-ok/…`，否则风控静默拒。
8. 公共 query 的版本身份来自 `SingleAppContext.getVersion` / `getVersionCode`，
   写死 `7.4.3.32` / `74332`。signer 已按这个改，UA 里的版本段跟着常量走。

### 6.4 首页 tab 是怎么发出去的（`bookmall.b0`，classes16.dex）

`StaggeredFeedTab.Wi` 负责刷新。真正发请求的是 `com.dragon.read.component.biz.impl.bookmall.b0`。

请求对象在 `b0.f(CreateBookstoreTabRequestArgs)` 里逐字段写进 `rpc.model.BookstoreTabRequest`，再由 `b0.e` 补首屏：

- `tabType` ← args.a
- `offset` ← args.b，`sessionId` ← args.c
- `clientReqType` ← args.reqType
- `clientTemplate`、`filterIds`、`recFilterInfoList`、`imageShrinkDatasStr`、`screenWidthPx`、`bottomTabType`、`bottomTabTypeList`、`versionTag`、`sessionUuid`、`deviceLevel`、`unlimitedShortSeriesNextOffset`、`immersiveConsumedBookId`
- 首屏额外：`bottomTabType = BookStore`，`clientFetchUnlimitedMode = FIRST_FETCH`，`imageShrinkDatasStr` 用 `ImageShrinkScene.STAGGER_FULL_COL` + `ImageShrinkType.DoubleCol` 按屏幕宽度生成，`bizConfigCtxInfos` 来自 `BizStaticConfigScene.BookMallDSLConfig`

`b0.m` 发送时分三支（同一份 `BookstoreTabRequest`）：

1. 极端预加载且 surl 流还没回：`NsCommonDepend.surlStreamApi()`，日志是「首次preload，等待surl合并接口的chunk返回」。
2. `b0.x()` 为真：`b0.b`。`PBModelConvert.convertBookStoreRequest2PB` 转成 `pbrpc.BookstoreTabRequest`，再调 `ai6.a$a.bookstoreTabRxJava`。该方法的注解是 `$GET /reading/bookapi/bookmall/tab/v:version/`。响应 `pbrpc.BookstoreTabResponse` 经 `b0.d` → `PBModelConvert.convertBookStoreResponse` 转回 `rpc.model.BookstoreTabResponse`。
3. 否则：`rpc.rpc.c.d(BookstoreTabRequest)`。`c$a.bookstoreTabRxJava` 的注解同样是 `$GET /reading/bookapi/bookmall/tab/v:version/`，模型是 JSON 那一套。

另一条注解 `$GET /reading/bookapi/bookmall/tab/v`（没有 `:version`）挂在 `ai6.a$a.bookstoreTab2RxJava` 上。`b0.b` 没调它。

响应往下读的字段（`BookstoreTabResponse`）：`code`（`BookApiERR`）、`message`、`logId`、`commonAbInfo`、`data`（`TabDataList`）。`TabDataList` 只有 `tabItem`、`tabIndex`、`orderData`、`coldStartInfo`、`authDouyinCode`。`b0.F` 取的是 `data.tabItem`。

### 6.6 翻页和取流（源码声明，不是猜的 query 样例）

翻页：`rpc.rpc.c.c(GetBookMallCellChangeRequest)`，注解 `$GET /reading/bookapi/bookmall/cell/change/v:version/`，方法名 `bookMallCellChangeRxJava`。调用方包括 `BooksRankListHolder` 和多个 `shortvideo.impl.datacenter`（`RecommendDataCenter`、`ActorVideoInnerDataCenter` 等）。请求类 136 个字段，首页会用到的包括 `cellId`、`filterIds`、`clientReqType`、`clientTemplate`、`imageShrinkDatasStr`、`offset` 一族。

取流：`seriessdk...rpc.d$a`。

| 方法 | 注解 | 请求类 |
| --- | --- | --- |
| `mGetVideoModelV2RxJava` | `$POST /novel/player/multi_video_model/:dr_scene/v1/` | `MGetVideoModelV2Request` |
| `mGetVideoDetailV2RxJava` | `$POST /novel/player/multi_video_detail/:dr_scene/v1/` | `MGetVideoDetailV2Request` |
| `getVideoModelRxJava` | `$POST /novel/player/video_model/v1/` | `GetVideoModelRequest` |

`MGetVideoModelV2Request` 四个业务字段：`bizParam`（`GetVideoBizParam`）、`drScene`、`mixedVideoIdMap`、`novelCommonParam`。`GetVideoBizParam` 含 `deviceLevel`、`detailPageVersion`、`disableVideoRelateBook`、`needAllVideoDefinition`、`needMp4Align`、`screenWidthPx`、`source`、`useOsPlayer`、`useServerDns`、`useServerDnsScene`、`videoPlatform`、`fromVideoId`。

发送点是 `wb5.s0.f`（证据 `ev_96d9639a7e2dffd22a632b2aab38d490b160aa195376f5cda3ceef24a9a24387`）。它先把 `useServerDns=true`、`useServerDnsScene=cold_start_stage` 写进 biz。`VideoPlayerApiDrSceneV715.enable` 缺省是 false，于是不走带 `:dr_scene` 的 V2，而是把 biz、`novelCommonParam`、`mixedVideoIdMap` 抄进 `GetVideoModelRequest`，调用 `mGetVideoModelRxJava`。`GetVideoModelRequest` 的 JSON 名是 `video_id`、`biz_param`、`content_type`、`mixed_video_id_map`、`NovelCommonParam`（证据 `ev_9ffb80bc7b3ef747edbd69de60f8dde5fd311256ff2409b5ee75b1e24ebc6f18`），没有 `dr_scene`。

`DeviceLevel` 的 wire：Low=1、Middle=2、High=3（证据 `ev_3b8202a964d32fbba92ff1936efb823e2c71300a04397e4bf36b650599fe085a`）。`VideoPlatformType.Mixed` 的 wire 是 1024，`Outer` 是 3（证据 `ev_d17edce52eefc329b9eb606b87a9b78e28824eab9310139fb0b1bb9456f46580`）。预取 `j45.d1.a` 把平台写成 Mixed；信息流外的预取 `drScene=preload`，其余是 `player`，但默认 AB 关闭时这个字段不会进 body。

单集是 `uu4.b.a` → `s0.g` → `getVideoModelRxJava`。平台参数为空时写成 Outer。`MultiVideoModelOpt.enable` 缺省 false，于是写 `videoIdType`、不写 `content_type`。普通剧集 `ft4.f$a.a` 把 `videoIdType` 设成 `VideoId`（wire 0）。`SeriesResolutionABValue` 的合成构造把 `requestAllDefinition` / `requestMp4Align` 置 false。桌面端单集按这个缺省分支发。

响应 `MGetVideoModelResponse.data` 是 `Map<String, SaaSVideoModelData>`（证据 `ev_656462853553e6b41b63e7dd46aa9728aba83c58cae6a83afb7ce6bfe6a29ebf`）。`videoModel` 的 JSON 名是 `video_model`（证据 `ev_964b7037489acbbe6958b8e7e5e536785e95270e20410c7cd3d1677e45fb7897`），桌面端按 `data.{vid}.video_model` 解析，这一段不用改。

RPC 的域名不在 `s0` 里，由 `gg1.j.e` 按接口类创建。桌面端主域仍是 `reading.snssdk.com`，末跳仍是 lq。

进度：`c$a.updateReadHistoryRxJava` → `$POST /reading/bookapi/read_history/update/v:version/`；`uploadReadProgressRxJava` → `$POST /reading/bookapi/read_progress/upload/v:version/`。
